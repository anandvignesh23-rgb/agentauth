# Fixture Boundary Inventory

Search terms reviewed: `mock`, `fake`, `stub`, `demo`, `simulate`, `random`, `hardcoded`, `TODO`, `FIXME`, `placeholder`.

| Location | Behavior | Classification | Action |
| --- | --- | --- | --- |
| `backend/seed.js` | Creates demo consumer, agent, merchants, orders, delegations, and demo key files. | Explicit demo data | KEEP AS EXPLICIT DEMO DATA |
| `data/demo-agent-private.pem` | Demo private key generated by seed script. | Explicit demo secret | KEEP FOR LOCAL DEMO; do not commit real keys |
| `backend/payments/provider.js` `FixturePaymentProvider` | Deterministic local/test payment provider contract simulation. | Fixture provider | KEEP ONLY WHEN `PAYMENT_PROVIDER=fixture`; disabled in production |
| `backend/payments/provider.js` `RazorpayTestProvider` | Real backend call to Razorpay Test Mode orders API. | Real integration | USE FOR BUILDATHON WITH TEST CREDENTIALS |
| `sdk/examples/demo-agent.mjs` | Runs demo attack/allow scenarios. | Explicit demo runner | KEEP AS EXPLICIT DEMO DATA |
| `frontend/security-lab.html` | Attack simulator buttons. | Real backend scenario runner using demo key | KEEP AS EXPLICIT DEMO DATA |
| `backend/server.js` `/v1/dev/reset` | Resets demo data. | Demo-only endpoint | KEEP FOR DEMO; protect/disable in production |
| JSON store | Local demo/test persistence. | Explicit local fallback | KEEP FOR LOCAL MODE; production uses Supabase/PostgreSQL |

Critical payment boundary: Razorpay order creation is not silently faked. If `PAYMENT_PROVIDER=razorpay` and credentials are missing, the API returns `RAZORPAY_NOT_CONFIGURED`. Fixture mode must be explicitly selected and is disabled in production.
